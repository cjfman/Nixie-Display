I want to add a new block to the Animation DSL named `sandbox`. All handlers for this block should be in a new file `animation_sandbox.py`. This block will be used to assemble predefined animations from the `animation_library.py` file.
Each line is one of the following types:
- assignment: Assign an expression to a variable
- print: Create an animation from a variable
- set: Set a setting value

# assignment
Assignment lines start with a variable name followed by a `=`. The remainder of the line will be a sudo-executable python like expression. This expression will be assigned to the variable. The expression can only contain:
- Functions from the `animation_library.py`
- Integer, float, and string literals
- Variables previosly defined by earlier lines in the block
- Operators `+` and `*`
- White space between tokens
- A list, using the python syntax, of objects of the same type. 

## Variable names
Variable names should always match this regex `[A-z]\w+`. Variable names cannot be any of the animation file key words, any pyxielib class name, nor anything from this list:
- set
- print

## Evaluation
Variables should be stored in a dictionary keyed by the variable name. This namespace should be separate from the animation file namespace. Variables must be an instance of a class defined in `animation.py`. Parameters to the functions may only be defined variables or literals. If the function doesn't exist, prepend `make` to the name of the function and search again. Only string literals may be used as non-parameters. String literals that aren't parameters should be converted to a `FullFrame` via the `textToFrames` function.

## Safety
Do not implement this by executing each line as python, as this would be unsafe. Instead, tokenize each line. Create a new `expression` array and make a second pass over the list of tokens. When making this second pass, construct objects and add the object to the new array. Evaluate the `expression` array using order of operations, (i.e. `*` then `+`). 

# set
The `set` keyword allows the use of `settings`. These settings can be any literal type, unless otherwise specified. A `set` line starts with the world `set`, followed by a setting name, a `=`, and a literal string, integer, float, or None. Only these settings exist:
|name|type|default value|
|----|----|-------------|
|delay|float|The `scale` value from the animation file|
|rate|float|0|

The namespace used for settings is separate than the one used for sandbox animation variables.

## type checking
The variables `delay` and `rate` may never be negative, nor can both be non-zero at the same. Whenever one is set to a non-zero value, the other should automatically be set to zero.

# print
Sequences should be added to the animation using the keyword `print`, which will start the line followed by a variable. If the variable isn't of instance `FullFrameAnimation` or `TubeAnimation`, then it should be converted to one. Classes should be transfored in this way, substituting `$<setting>` with the value from the settings table:
- `Frame` > `FullFrameAnimation([$delay, FullFrame(x)])`
- `FullFrame` > `FullFrameAnimation([$delay, x])`
- `List[FullFrame]` > `FullFrameAnimation.makeTimed(x, delay=$delay, rate=$rate)`
- `TubeSequence` > `TubeAnimation([x])`
- `List[TubeSequence]` > `TubeSequence.makeTimed(x, delay=$delay, rate=$rate)`
